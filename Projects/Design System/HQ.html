The copy workbench reads every line the system shows

All the copy Re.SOURCE and Colour LINGO put in front of a person, in one place, with a verdict required on each line. The deck is generated from the live surfaces rather than written by hand, so it cannot quietly disagree with what ships: the walkthrough's six chapter titles and bodies, the four gloss sets of twelve, the twelve position reads, the legends and announced lines, and the paragraph the whole system is explained by.

Two of the 82 are live: the chapter-two and chapter-three titles read off the position table, so a Sheet move renames them by itself. The workbench refuses to edit those, in the handler and not only in the markup. That rule survived as prose through four lanes; it took ten lines of code to make it impossible to break.

Every line takes a verdict, the kept ones included, and the note says why — a sweep that rewrites everything has no judgement in it. A reading survives a re-extraction; an edit whose surface moved underneath it is dropped, the line reopens and says so. The changes handoff names each line's source, before and after, so a verdict can be applied without guessing which string was meant.

Words we use

Glossary

A term, where it is defined, and the short form. The queue and the rulings moved here. A browser flag is not a decision.

On the sheet

fitWhether a word deserves its position, rated by hand

Rated by hand, never computed. Quality checks count what can be counted, and whether a word is the right word is not one of those things. A word is rated inside its set, so the same word can fit one set and not another. Unsettled is the default: the store starts by admitting it has not judged yet rather than claiming everything is fine.

reasoning.md, "The two ratings", 27 Aug 2026.

caseThe written entry arguing a cell's fit

Not defined in reasoning.md, only in code comments. A case proposes a fit for the exact word it was written about. If that word is swapped out, the case goes stale rather than silently carrying over.

Colour LINGO, near caseHere and fitAt, settled 28 Aug 2026.

poolUnsorted candidates, kept apart from the grid

823 unsorted candidates sit below the four settled rows. Loading them into the grid as alternates was tried and reverted the same day. At fifty to seventy words a cell, the grid stopped being an overview. Nothing in the pool is pre-assigned to a set. Length narrows which set could take a word, and does not always decide it.

reasoning.md, "the pool is a separate file from the seed", 26 Aug 2026.

driftSheet and deck naming different words at one spot

One-directional. LINGO is the source, so a mismatch is reported as the deck being stale, not as a conflict to resolve. The deck is left alone regardless. A new store has to prove itself before it starts overwriting the thing it replaced.

reasoning.md, "drift is one-directional", 26 Aug 2026.

fault / qualityWhat is countable, without judging meaning

Four checks, all countable, none about meaning: no word, wrong length for the set, used twice anywhere in the sheet, contradicts a printed card. Deliberately does not score whether a word is the right word. That judgement is what the platform exists to support, not replace.

reasoning.md, "quality marks only what can be checked", 26 Aug 2026. Colour LINGO, wordFaults.

registerMatch to a set's name, for example Anchor TAG

Not a system rule. It appeared only in the rescore spec as a proposed signal, a proposal, not something reasoning.md or the code establishes. The choice is waiting above.

notes/lingo-fit-rescore-spec.md.

asks / readsThe two prose fields inside a case

Not defined as terms in the system's own vocabulary. Asks names the semantic field a position's pool of candidates is about. Reads is the argument for or against the settled word. Both were named while writing lingo-cases.js.

templates/colour-lingo/lingo-cases.js.

While building

holeA slot in a template, filled at render

Written {{ path }} and nothing more: a dotted lookup, never an expression. {{ a + b }} and {{ fn() }} fail silently, so anything computed is worked out in the logic class and exposed by name. A hole renders nothing until the logic lands, which is why a hole in the wrong place stops a design painting.

reasoning.md, "Retired: the sanctioned style hole", 5 Sep 2026.

style holeA hole inside a style attribute, almost always wrong

A holed CSS property cannot paint until the logic class arrives, so the design streams in half-dressed. Legitimate only when the value cannot exist at parse time and nothing else can carry it. On SVG something always can, which is how the last one in the system was retired.

reasoning.md, 5 Sep 2026.

presentation attributeSVG's own attributes, where a live value belongs

fill, stroke, opacity, r, cx. SVG styling written as attributes rather than CSS. A hole in one is free of the style-hole problem: the layout stays literal and paints with the markup while the live part rides on the attribute. Colour FLOWER established the technique. Brand STYLE's position strokes now use it.

Colour FLOWER, the data-fade comment.

logic classThe half of a component that computes

A Component extends DCLogic class holding state, handlers and lifecycle. Its renderVals() returns the values the template's holes read by name. Anything that would be a ternary, a map or a comparison in markup belongs here.

A design component's own script.

mountWhen an element first appears in the page

The distinction that decides which kind of motion is available. Keyframes fire on mount, so anything that appears when hovered or selected can animate in. A transition needs an element that persists across the change, so a thing already on screen animates by transition instead. Colour FLOWER's pop uses both: petals mount, the core persists.

Colour FLOWER.

DCA .dc.html file: template, logic and props in one

Opens directly in a browser, can be imported by other components, and paints from the first character streamed rather than after the whole file lands. Templates in this system are design components so a consuming project has one file to copy and one line to edit.

The masters under templates/.

tweakA prop with an editor, surfaced as a control

Declared in a component's props JSON with an editor kind and a default. Reserved for what in-place editing cannot do: behaviour, alternative treatments, one flag that changes many elements at once. Copy and single colours are edited directly, so they are never tweaks.

A component's data-props.

overshoot / popMotion that passes its end value and comes back

A bounce. Banned everywhere motion reports position, where the movement is the message and a bounce claims a move that did not happen. Allowed on hover, which reports only the pointer: cubic-bezier(0.34, 1.56, 0.64, 1) at 360ms, the fourth curve. Ruling, 5 Sep 2026.

Brand STYLE, Motion.

tokenA named value in the global stylesheet

A CSS custom property in styles.css and what it imports, read by every surface as var(--space-lg). The compiler counts them, so a value that is a token is a value the whole system can be checked against.

styles.css and tokens/.

latticeThe deck's grid law: one sheet, one gap, whole rows

Five rules, stated in the Word DECK master's own header and checked by the deck-grid test: one lattice (every band is a grid on the same tracks, every cell spans whole slots), one gap (the same number inside a cell, between cells and between rows; the seam is an overlap, not a second gap), the count divides the deck (six, four, three, two or one, the widest that fits the measured frame; closed stack uses six, three, two or one, because four cannot hold its six holdings whole), nothing stretches (leftover space is margin, never a gutter), and a two-card cell fits its row.

reasoning.md, "One lattice for the deck", 21 Sep 2026.

holdingOne cell of the deck: a card, or two cards read as one

The word the deck's law is written in, because the grid counts cells and the deck counts cards. Full pair, a Pair is one holding across two slots. Bands are made of holdings, not cards: twelve Singles pair into six, twelve Pairs are six, and the lead band is four.

helmetThe part of a design component that lands in the page head

A helmet block at the top of a component's template. Its children, font links, font-face, keyframes, body resets and script tags, move into the document head and mount as soon as the tag closes, before the rest of the page has streamed. It is the one place a design component may declare CSS rules rather than inline styles, which is why the August audit found the same law copied into nine of them. The field and the motion vocabulary were pulled out into the compiled stylesheet for that reason.

cascade hazardTwo rules of equal weight, and the later one silently wins

CSS resolves a tie in specificity by document order, so of two rules that are equally specific the one declared later applies. The base script appends the stylesheet link after a component's helmet, so a helmet rule and a stylesheet rule of the same weight go to the stylesheet. Twice in one session: eight greyscale tiles lost their span to a grid-child rule, and every root marked both grid and sub lost its columns to subgrid, which computes to nothing without a grid parent. Neither threw an error. The layout quietly collapsed, which is what makes it a hazard rather than a bug.
